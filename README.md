# Тестовое задание для Bitrix-разработчика

Решение заданий из [todo.md](todo.md). Рассчитано на коробочный Битрикс24, PHP 8.1+ и модули CRM, Highload-блоки и UI. Нужен новый API CRM с поддержкой смарт-процессов.

## Файлы задач

Основной код находится в `local/php_interface/figura/tasks/`:

1. [01_create_hl_block.php](local/php_interface/figura/tasks/01_create_hl_block.php) — создание HL-блока «Оборудование», полей и трёх тестовых записей.
2. [02_create_smart_process.php](local/php_interface/figura/tasks/02_create_smart_process.php) — создание смарт-процесса, сделки и связанного элемента.
3. [03_equipment_component.php](local/php_interface/figura/tasks/03_equipment_component.php) — получение оборудования, фильтрация, сортировка и пагинация.
4. [04_smart_process_tab.php](local/php_interface/figura/tasks/04_smart_process_tab.php) — вкладка «Оборудование» в карточке смарт-процесса.
5. [05_deal_equipment_count.php](local/php_interface/figura/tasks/05_deal_equipment_count.php) — количество оборудования под полем «Клиент» в сделке.

Общие функции вынесены в `common.php`. Сам компонент лежит в `local/components/figura/equipment.list/`, скрипт и стили счётчика — в `local/js/figura/equipment/`. В каждом PHP-файле есть пояснение.

## Как подключить

1. Скопировать папку `local/` в корень тестового портала, включая скрытые файлы компонента и каталог `.default`.
2. Добавить в существующий `/local/php_interface/init.php`:

   ```php
   require_once $_SERVER['DOCUMENT_ROOT'] . '/local/php_interface/figura/init.php';
   ```

   Если файла нет, создать его с `<?php` и этой строкой.

3. Открыть `/local/tools/figura/install.php` под администратором. Нажать «1. Создать структуру», затем «2. Создать тестовые данные». Два запроса нужны, чтобы обновились метаданные ORM.
4. Перейти по ссылкам на созданную сделку и элемент. Повторный запуск использует существующие записи. ID тестовой сделки и элемента хранятся в опциях `main` с префиксом `figura_equipment_demo_`.

Для обычных сотрудников нужно выдать права на чтение сделки и смарт-процесса. Пользователю №5 они тоже нужны. Если в CRM настроены дополнительные обязательные поля, заполнить их в `createItem()` задачи 2.

## Как работает

Оборудование хранится в HL-блоке `FiguraEquipment` (таблица `b_figura_equipment`). В нём четыре поля из брифа. `UF_TYPE` хранит ID варианта списка, `UF_DEAL_ID` — ID сделки.

Смарт-процесс «Учёт оборудования» связан со сделкой через `RelationManager`. Смарт-процесс — отдельная сущность CRM, а бизнес-процесс — сценарий действий над её элементом. Дизайнер БП и роботы включены; отдельный сценарий в задании не требуется.

Компонент использует `main.ui.grid` и `main.ui.filter`. Фильтрует по названию, типу и дате, поддерживает сортировку и страницы. Условие по сделке задаётся сервером и остаётся при сбросе фильтра. Для самостоятельного вызова после пролога:

```php
$APPLICATION->IncludeComponent('figura:equipment.list', '', [
    'DEAL_ID' => 123, // ID сделки на портале
    'CACHE_TYPE' => 'N',
]);
```

Вкладку добавляет событие `onEntityDetailsTabsInitialized`. При её загрузке сервер определяет сделку по элементу смарт-процесса и проверяет права на обе записи. Если связь отсутствует или сделок несколько, компонент выводит пояснение. Доступ к оборудованию определяется правом чтения связанной сделки.

Счётчик подключается через `OnProlog` на странице `/crm/deal/details/{ID}/`. PHP получает количество из HL-блока, JS вставляет текстовый блок под «Клиентом». Поле нельзя редактировать; для текущего пользователя с ID 5 оно выделено цветом. Количество обновляется при открытии или перезагрузке карточки.

Счётчик зависит от разметки веб-карточки: после обновления Битрикса нужно проверить селекторы `CLIENT`/`CLIENT_ID` в JS. Поле «Клиент» должно быть видно. Ошибки пишутся через `AddMessage2Log`. Для отключения достаточно убрать подключение из `init.php`.

## Проверка

На живой коробке код не запускался. Локально проверены синтаксис PHP/JS и построение фильтра и сортировки:

```bash
php tests/query_test.php
node --check local/js/figura/equipment/deal-count.js
```

На портале проверить установку без дубликатов, три строки во вкладке, фильтры и пагинацию. В сделке должно отображаться число 3, после изменения HL-блока и перезагрузки — новое количество. Проверить выделение под пользователем №5, обычное оформление под другим и отказ в доступе сотруднику без прав. AJAX-запрос без сессионного токена должен возвращать 403.

Использованная документация: [HL-блоки](https://dev.1c-bitrix.ru/api_d7/bitrix/highloadblock/highloadblocktable/index.php), [связи CRM](https://dev.1c-bitrix.ru/api_d7/bitrix/crm/relation.php), [вкладки карточки](https://dev.1c-bitrix.ru/api_d7/bitrix/crm/systemcomponents/crmentitydetails.php).
